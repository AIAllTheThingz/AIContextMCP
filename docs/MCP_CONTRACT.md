# MCP contract (implemented SDK 2.2 stdio surface)

Mutation request IDs use `<issued-UTC-epoch-seconds>:<lowercase-D-UUID>`.

The initial server exposes exactly these eight tools. All use strict JSON, typed input/output, bounded lists/strings, UTC timestamps, project scoping, and a common error envelope. `project.bootstrap` is statically `ReadOnly=false` because `register=true` can mutate, but defaults to read-only; other read tools are read-only and record tools mutate. Every mutation includes `requestId` exactly `<issued-UTC-epoch-seconds>:<UUID>`. Replay keys are `(scope,tool,requestId)`, with scope `projectId` or registration `canonicalRoot`; the durable receipt is written in the same transaction. Before writing, reject future timestamps over 60 seconds or age over 30 days; retain receipts for 30 days and never reapply an expired/evicted key. Same canonical payload returns the receipt; different payload is `Conflict`; unknown outcome retries the same key, while a new UUID is a new intent. Mutations use `expectedVersion` and a server snapshot-token precondition; failure writes nothing.

Common limits: every request 64 KiB UTF-8 and response 32 KiB (bootstrap 16 KiB); the effective response-budget minimum is 8 KiB for configurable `maxBytes` and bootstrap configuration, because protocol envelope/text duplication reserves 4 KiB. Unspecified strings 1,024 UTF-16 units; IDs/paths/remotes 512; titles 256; summaries 8,192; content 32,768; query 256; arrays 100 items plus aggregate cap. `maxBytes` defaults 16 KiB and accepts 8–32 KiB. Cursor max 1,024 chars, expires 15 minutes and is bound to scope/filters. Limits reject rather than truncate. Search ordering is `observedUtc DESC`, then ID ascending; `branch` filters select branch-scoped records, with exact commit filters taking precedence; no arbitrary FTS/query syntax.

Common types: `Snapshot { snapshotToken, canonicalRoot, branch?, head?, workingTreeFingerprint, observedUtc, completeness }`; `Reference { projectId, repositoryId?, kind=repository-document|artifact|record|external, id?, relativePath?, uri?, hash? }`; `Source { kind, reference?, observedUtc }`. References are server-controlled and scoped; external URLs are never fetched. `snapshotToken` is opaque, server-issued, and scope-bound. Bootstrap `git` is a Snapshot; `observedSnapshot` and `runSnapshot` identify server observations, with runSnapshot historical and verified against evidence, not trusted as a caller assertion. Success is `{ ok:true,data,error:null,schemaVersion:1,correlationId }`; failure is `{ ok:false,data:null,error:{code,message,correlationId,retryable},schemaVersion:1 }`, without stack traces. Invalid JSON, unknown fields, missing scope, cross-project references, identity conflicts, limits, unsafe paths, secret-shaped content, stale preconditions, and storage failures map to stable codes including `CrossProjectReference`, `PathRejected`, `LimitExceeded`, `SecretRejected`, `StaleState`, `Conflict`, `DatabaseUnavailable`, `DatabaseCorrupt`, `GitUnavailable`, and `InternalError`. Expected snapshot tokens are required for phase transitions and decision/finding/handoff changes asserting current state; unknown observations cannot authorize transitions. There is no content-fetch or preview/apply tool. Artifact workflow is operator-staged sanitized evidence under the artifact root; record validates regular file, scope, size, and server hash before an append-only Artifacts row; no arbitrary absolute `artifactRef`.
`UnbornRepository` is returned when a validated Git repository has a valid branch HEAD but no commit; unsafe, missing, or rejected paths continue to use `PathRejected`.
